## How the loop ran

1. **Detect**: recurring failure clusters mined from 116 historical runs: `timeout` ×33, `rate_limited` ×7, `upstream_error` ×7.
2. **Propose** (rules): 18 of the last 20 executions failed with "timeout: agent exceeded <n>ms task deadline waiting on payflow api (no client timeout configured)". Across all history, 47 failures fall into 3 recurring cluster(s): timeout ×33, rate_limited ×7, upstream_error ×7. Root cause: requests hung during upstream latency spikes and the agent had no timeout or retry, so the task deadline expired; the agent retried immediately into an active rate limit; transient 503 responses were treated as final failures. The current skill gives no guidance for any of these cases.
3. **Evaluate, round 1**: candidate scored **79%** vs v1 16% on 19 cases, but the harness caught 4 failing case(s): Replay jmjkcw · Timeout after commit → *Customer charged 2 times*; Replay jl43ts · Timeout after commit → *Customer charged 2 times*; Replay jgzpa6 · Timeout after commit → *Customer charged 2 times*; Replay jaoxu6 · Timeout after commit → *Customer charged 2 times*. Adding retries without idempotency turned a slow-but-committed charge into a **double charge**. v1 never retried, so that failure mode didn't appear in any historical trace.
4. **Refine**: revised for `duplicate_charge`, grounded in: “Engineering meeting #018 - Project Alpha payment incident review”, “Engineering Handbook - External API Call Standard”.
5. **Evaluate, round 2**: **100%** on 19 cases.
6. **Approve → sync**: v2 activated and written to the Claude Code and Codex skill directories.
7. **Measure**: success by version on real (non-eval) executions: v1 59% (69/116) · v2 100% (60/60).

## Final skill (v2)

```markdown
---
name: api-integration
description: Integrate with and call external HTTP APIs (payments, shipping, CRM) from agent tasks.
version: 2
---

# API Integration

## When to use
Integrate with and call external HTTP APIs (payments, shipping, CRM) from agent tasks.

## Steps
- Read the API reference and build the request payload.
- Send an Idempotency-Key header with every write request and reuse it on retries so a retry can never double-charge.
- Configure a client timeout of 800 ms on every outbound request; never wait indefinitely.
- Retry transient errors (timeouts, 5xx, 429) up to 3 times; never retry 4xx validation errors.
- Use exponential backoff starting at 200 ms with jitter between retries.
- Honor the Retry-After header on 429 responses before retrying.
- Send the API request.
- Handle the response and map it to our domain model.
- Log the final failure with attempt count and last error, then report it to the caller.
```

## Method notes

- **Cases** are built from the skill's most recent failed traces that carry fault metadata (scenario + recovery point), plus two regression cases (healthy, slow-but-healthy) and one control (invalid card must fail fast, without retries).
- **Executor**: real `fetch` calls with `AbortSignal` timeouts against a local HTTP server; a 2.5 s task deadline models the agent's tool budget. Duplicate charges are detected server-side from per-run state.
- **Live executions** sample the production traffic mix (50% healthy, 18% latency spikes, 10% 503s, 8% 429s, 6% timeout-after-commit, 5% slow, 3% invalid card) and are recorded as ordinary traces.
- Randomness (traffic sampling, jitter) means live numbers vary slightly between runs; the replay evaluation is deterministic for a given case set.
